# ReefVision-Edge session export v1

An export ZIP always contains `manifest.json`, `frames.csv`, and `detections.csv`. It also contains `monitor.mp4` when monitor recording was enabled and may contain `operator-profile.json` when ONNX Runtime profiling was enabled. The manifest schema identifier remains `reefvision-edge-session/v1`; frame rows use `reefvision-edge-frame/v1` and detection rows use `reefvision-edge-detection/v1`.

Coordinates are floating-point `xyxy` values in original source-frame pixels. Frame indices are zero-based. For constant-frame-rate recorded sources, `timestamp_ms` is derived as `frame_index / reported_fps * 1000`; the manifest records this basis. Empty timestamps are permitted for live sources.

The manifest records session state and metrics, sampling, thresholds, class map, source dimensions/codec/hash, model and metadata SHA-256 hashes, requested and actual compute devices, the active provider, a fallback explanation, and ONNX Runtime operator-profile counts. It also records the two recording flags and independent preview/saved-video overlay settings. If data recording was enabled, the manifest's `frames` array and `frames.csv` preserve every processed frame, including frames with zero detections, together with dimensions, timestamp, inference status, latency, and detection count. When data recording was disabled, aggregate session counts remain in the manifest while both CSV files contain headers only. Consumers must reject unknown schema identifiers, unsafe ZIP paths, mismatched persisted counts/classes, invalid hashes, and coordinates outside the corresponding frame dimensions.

Desktop ReefVision commit `e94dad6a3bece7b776bf45776bc5d06cfbc2c0dc` does not define an import contract for frame-level Edge detections. This v1 schema is therefore a native Edge contract; desktop import remains follow-up work.
